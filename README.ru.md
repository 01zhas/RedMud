# RedMud

Библиотека выполняет только преобразование данных. Источники, запись результатов,
повторы и транзакции остаются ответственностью приложения. Python 3.11+ и Rust
stable нужны для сборки из исходников: `python -m pip install .`.

```python
from redmud import Pipeline, field as F
p = (Pipeline().require({'price': 'int', 'quantity': 'int'})
     .check('positive', F('quantity') > 0)
     .derive('total', F('price') * F('quantity')))
assert p.run_one({'price': 1000, 'quantity': 3}).value['total'] == 3000
```

Pipeline выполняет выражения и обработку вложенных списков в Rust.
Runtime/Processor сохраняют обычную бизнес-логику Python, включая пользовательские
классы. Автоматического ускорения произвольных Python-функций нет.

Методы run_one, run_batch, run_iter возвращают результаты с ok, value, errors,
index. Политика collect сохраняет ошибки, raise выбрасывает ProcessingError после
обработки пакета, skip фильтрует отклонённые записи в пакетах и итераторах.
run_iter ограничивает буфер размером batch_size. Ошибка одной записи не портит
другие. Денежные расчёты используют целые числа в минимальных единицах;
переполнение i64 вызывает ошибку. Входные записи не изменяются.

snapshot показывает метрики и настроенные профили полей; profile включает
cProfile/tracemalloc для ограниченной выборки. Последний не измеряет память Rust.
Текущая версия не поддерживает параллельные вычисления, дробную арифметику и
детальные тайминги стадий native. Конвертация словарей и результатов через JSON
создаёт накладные расходы. Это первая рабочая версия, а не сертификация production.

Проверка: `cargo test`, `python -m unittest discover -s tests -v`.
Примеры: `python examples/native_cart.py`, `python examples/cart.py`.
Замеры: `python benchmarks/benchmark.py`. Полное описание API, ограничений,
методики и миграции находится в английском README и docs/.

Изменения M1: prepare проверяет схемы и выражения до чтения записей. Границы
min/max должны соответствовать типу int/float; для number они не поддерживаются.
Целые значения сохраняются точно в диапазоне [-2^63, 2^64-1], выход за диапазон
возвращает numeric_range. Арифметика остаётся i64. Ключи словарей — строки;
кортежи и циклические структуры отклоняются в native-режиме.
Ошибки парсинга/вычислений имеют статус error, схемы/бизнес-правил — rejected.
При raise оба режима учитывают весь пакет; profile.records считает входы,
включая пропуски skip. Для разработки: `bash scripts/check.sh` после установки
requirements-dev.txt и компонентов clippy/rustfmt. В M2 реализованы ограничения
глубины и метрик; реальные CI-запуски пока ожидаются. Ускорение не заявляется.

Проверка T-206 перенесена в M1: PyO3 обновлён до 0.29.3 для устранения двух
RustSec advisory. `scripts/security.sh` проверяет notices и запускает отдельные
сканеры Rust/Python; установка инструментов описана в docs/development.md.
Лицензионные тексты включены в THIRD_PARTY_NOTICES.md и пакеты wheel/sdist.


В M2 предел глубины native-данных — 64: корень имеет глубину 1, скалярные листья
учитываются. Превышение возвращает depth_limit; планы, выражения и схемы
проверяются до чтения входа. Счётчик batch_sizes использует шесть фиксированных
категорий; batch_size_summary содержит count/sum/min/max. Неизвестные классы в
профилях типов относятся к other. Сырые записи в статистике не сохраняются.

Локально проверены wheel и установка из sdist для Linux CPython 3.11/3.12/3.13.
Команда `python scripts/package_check.py --python /путь/к/python` создаёт отдельные
venv, проверяет установленные импорты, тесты и примеры вне каталога исходников.
Workflow для Linux/macOS находится в .github/workflows/ci.yml; macOS не считается
проверенной платформой до реальных CI-запусков.
